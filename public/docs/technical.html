3. Permission System

Permissions are generated from config/admin-modules.php in format: {action}_{module}

// Example: config/admin-modules.php
'enquiries' => [
    'label' => 'Enquiries',
    'actions' => [
        'view' => 'View Enquiries',
        'create' => 'Create Enquiries',
        'edit' => 'Edit Enquiries',
        'assign' => 'Assign Enquiries',
        ...
    ],
],

// Generated permissions: view_enquiries, create_enquiries, edit_enquiries, assign_enquiries
// Checked in policies via: $this->canPerform($user, 'view', 'enquiries')
// Super admin bypasses all via Gate::before()

Total: 102 permissions across 18 modules, 4 default roles.

4. Activity Logging

Custom per-module tables (NOT spatie/activitylog). Each module has its own {module}_logs table.

// Tables: enquiry_logs, booking_logs, quotation_logs, tour_logs, page_logs
// Schema: id, record_id, user_id, action, description, old_values (JSON), new_values (JSON), ip_address, created_at

// Usage via trait:
class Enquiry extends Model {
    use LogsActivity; // Auto-logs create, update, delete
}

// Manual logging:
ActivityLog::log($booking, 'status_changed', 'Cancelled by admin', ['status'=>'confirmed'], ['status'=>'cancelled']);

// Querying:
ActivityLog::getLogsFor($enquiry); // Returns collection from enquiry_logs table
The ActivityLog model dynamically sets its table based on the model class. No polymorphic queries needed.

6. Key Workflows (Code Flow)

Contact Form → Enquiry

POST /contact-us
  → ContactController@submit
  → Validates (name, phone required)
  → Creates Enquiry (status=new, source=website)
  → LogsActivity trait logs "created"
  → EnquiryObserver fires → notifies sales+admin
  → Checks repeat client → notifies if repeat
  → Returns JSON (AJAX) or redirect (normal)

Quotation Send → Email + Notification

Admin clicks "Mark as Sent" on EditQuotation page
  → Updates status to 'sent', sets sent_at
  → Creates quotation_history record
  → Sends QuotationSent mailable to client_email
  → QuotationObserver fires (status changed to 'sent')

Client Views Quotation

GET /quote/{publicId}
  → QuotationController@show
  → Increments view_count
  → If first view: sets viewed_at, changes status to 'viewed'
  → Creates quotation_history (event: viewed)
  → QuotationObserver fires → notifies prepared_by user

Payment Recording → Balance Update

Admin adds payment via PaymentsRelationManager
  → Payment created (status=received)
  → PaymentObserver fires → notifies admin
  → updateBookingBalance() called:
    → Sums all received payments
    → Updates paid_amount, balance_amount
    → If balance ≤ 0 → status = fully_paid
    → If balance > 0 but paid > 0 → status = partial_paid
    → Creates booking_status_history if status changed

7. Razorpay Integration

Feature Flag: setting('razorpay_enabled') must be 'true'

Flow:
1. Client opens /pay/{publicId} → RazorpayController@paymentPage
2. Clicks Pay → JS calls POST /pay/create-order
3. Controller creates Razorpay order via API (curl)
4. Stores in online_payments table (status: created)
5. Returns order_id + key_id to frontend
6. Razorpay Checkout.js opens payment modal
7. On success → JS calls POST /pay/verify
8. Controller verifies HMAC signature
9. Updates online_payments (status: captured)
10. If booking linked → creates Payment record → updates balance

Security:
- Signature: hash_hmac('sha256', order_id|payment_id, key_secret)
- Keys stored in settings table (not .env)
- All responses logged in gateway_response JSON column

8. Frontend Performance

Optimizations applied:
- InstantClick.js (prefetch on hover → instant navigation)
- CSS: flatpickr, glightbox loaded with media="print" onload (non-blocking)
- JS: flatpickr, glightbox loaded with defer attribute
- Removed: AOS.js, Select2 from global load
- Google Analytics: conditional (only if setting exists)
- Images: lazy loading via browser native
- Fonts: preconnect + single font family (Inter)

9. SEO Implementation

Every page gets (from layout):
- <title> from @yield('title') or setting('seo_title')
- <meta description> from @yield('meta_description') or setting('seo_description')
- <link rel="canonical"> = current URL
- Open Graph: og:type, og:title, og:description, og:url, og:site_name
- Twitter Card: summary_large_image
- JSON-LD: TravelAgency schema (name, phone, email, address)

Per-page (admin-editable fields):
- Tours: meta_title, meta_description, og_image
- Destinations: meta_title, meta_description, og_image
- Posts: meta_title, meta_description, featured_image (as og:image)
- Pages: meta_title, meta_description, og_image

1. Set APP_ENV=production, APP_DEBUG=false in .env
2. Configure MySQL credentials
3. php artisan migrate --force
4. php artisan db:seed --class=RolesAndPermissionsSeeder
5. php artisan db:seed --class=AdminUserSeeder
6. php artisan storage:link
7. php artisan config:cache
8. php artisan route:cache

10. php artisan view:cache
11. php artisan filament:optimize
12. Set cron: * * * * * php artisan schedule:run
13. Configure SMTP in .env for email sending
14. Update Site Settings in admin (company details, Razorpay keys if needed)
15. Change default admin password

11. Known Gotchas

  • TourPricing model has protected $table = 'tour_pricing' (non-standard plural)
  • Blade: Never use @context or @type in templates — use @@context (escape for JSON-LD)
  • Blade: Never wrap @section inside @if on same line
  • Filament 5: Tables\Actions\Action namespace does NOT exist — use Filament\Actions\Action
  • Filament 5: Layout components (Section, Tabs) are in Filament\Schemas\Components\*
  • Filament 5: ChartWidget::$heading is non-static, TableWidget::$heading is static
  • DemoDataSeeder must NOT use WithoutModelEvents trait (breaks HasSlug auto-generation)
  • Migration order matters for FK constraints — bookings before payments before payment_histories
